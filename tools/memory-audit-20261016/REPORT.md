# 小智记忆机制只读核查

核查日期：2026-10-16（北京时间）。依据在线进程、正式发布包字节码、Python运行目录及生产数据库只读汇总。未修改生产代码、配置或数据，未触发记忆搜索、提取、模型、TTS或视觉请求。

## 结论

系统已有长期记忆、自动收集对话素材、后台批量提取和按需查询。普通聊天不自动搜索整个云端记忆库；长期记忆不等同于无限期保留全部原始聊天。有条件愿望还可能被事实过滤规则排除。因此保存“面试成功后去吃牛肉面”是必要环节之一，尚不足以保证数周后听见“拿到offer了”便自然接回。

## 1. 每轮先确定归属，再记录素材

服务端为每轮生成身份快照。云端路径要求账号和人物有效、处于personal模式且该轮身份为matched；默认身份仅有本地连续对话资格，不进入百炼云端个人记忆路径。

用户话语自动写入本地SQLite outbox，再异步送管理API；用户原话、助手回复、工具结果和对话结束标记分开保存到MySQL的`ai_person_material`。使用事件编号防止重复入库，检索回灌消息不重复作为提取素材。

这一步是归档素材，不是每句话都已提炼成长期事实。参考：`deployed/core/providers/memory/bailian/bailian.py`第26至62行，`deployed/core/utils/person_identity.py`第30至37行。

## 2. 自动提取是后台批处理

正式JAR的`MemoryDailyWorker`：北京时间每天03:00确定批次边界；后台每3秒检查任务，支持重启后的补处理。不是每3秒调用模型。

当前门槛为`memory.material.min-user-tokens`默认10000；未发现进程环境、包内配置或外部配置覆盖此值。估算只计算用户对话及显式事实，不把助手输出计入门槛；计数规则为汉字数/1.5加其他Unicode码点数/4，不能当成Qwen真实计费Token。

提取还要求正确人物归属、智能体仍启用百炼记忆、素材允许召回、完整对话结束标记，以及没有待处理更正或冲突任务。合格批次提交云端`add-async`，检查异步事件成功后才完成任务、推进水位并清理已处理素材。素材包含角色说明，要求从用户明确陈述和确认提取，后续更正优先，助手推测和内部工具资料不能成为个人事实。

数据库快照：当前活跃人物允许召回的用户素材44行，估算297 Token；当前人物有1条完成的提取任务，创建于2026-09-30 13:04:01。账号所有人物代次合计3条完成任务。没有看到此后新的提取任务记录。297远低于10000，不能把新对话归档视为已经完成新一轮云端提取，也不能仅凭任务记录推断云端当前还剩多少事实。

## 3. 显式保存是另一条入口

“记一下……”由主模型规划`memory_add(fact)`，程序检查身份和规范化事实，API立即写入`explicit_fact`，返回记录编号及版本并核验本地结果。因此不必等累计10000 Token，便可在本地查询到明确保存的事实；其云端整理仍属异步阶段。

更正和遗忘先找记录，以编号及版本定位；多目标限定于明确选中集合。修改后使短期摘要和查询缓存失效，覆盖/删除标记抑制旧素材和云端资料。不能把“本地已生效”说成“云同步已经完成”。

参考：`deployed/core/utils/recent_memory.py`第31至95行；`PersonMemoryService.javap.txt`的`add`与`override`；`RecentArchiveService.javap.txt`的`overrideRecord`。

## 4. 聊天时如何调取

### 自动带入的连续对话资料

- 已确认人物首次进入当前会话时，按账号、人物、身份代次、智能体恢复最近最多50个完整对话轮次。
- 已产生的压缩摘要可落本地SQLite，加载时有效期24小时；不会为了每句话另外调用摘要模型。
- 当前关闭云端人物画像，因此不会自动把云端完整个人档案注入每轮。`background()`主要返回可用的本地短期摘要。
- 18万Token是单次请求可容纳的上下文容量，不表示每次自动读18万Token历史，更不表示云端全部长期记忆都会出现在上下文里。

### 按需记忆检索

主模型通过Harness选择`memory_search`；明确的个人事实查询还会被规则要求本轮实际查询。缺少工具时可走已有一次补检。

一般相关查询先访问本地API，查近期用户聊天、未整理素材、显式事实和更正记录。本地按字面片段、少量同义词及时间排序，过滤非事实和已删除资料，每页最多8条。普通聊天历史查询窗口24小时，未整理素材和显式事实不使用同一个24小时条件。

本地有可靠结果就返回，不再合并云端结果；本地没有可靠命中且人物有云端资格，才查询百炼长期记忆，默认top_k=5、事实文本最多1500字符、API上游搜索期限默认850毫秒，语音服务外层约1秒。同一用户轮次复用搜索结果，避免重复付费查询。失败返回暂不可用，不能解释为用户没有该记忆。

事实列表`scope=facts`或按记录ID读回属于专用本地分支，不自动回退到云端；因此本地列表数量不能当成全库事实总数。

参考：`deployed/core/utils/recent_memory.py`第6至28行；`deployed/core/providers/memory/bailian/bailian.py`第64至101行；`RecentArchiveService.javap.txt`的`search`；`PersonMemoryService.javap.txt`的`search`。

## 5. 保存和主动想起之间的三个限制

1. 自动提取有日批次和累计门槛，一句随口的心愿不会马上被整理进云端。
2. “我拿到offer了”不属于当前强制记忆查询识别的典型表达。模型可以自行选择记忆工具或补检，但系统没有保证这一事件会触发相关旧心愿搜索；本地字面匹配也不保证把offer和面试成功联系起来。
3. 正式JAR的`RecentArchiveService.factualUser`会排除包含“假如、如果、也许、可能”等词的句子；这一过滤既用于本地查询，也用于云端返回事实的筛选，显式保存入口也使用事实校验。有条件的真实意愿可能被误当假设过滤。用户原例“要是成功了”不必然命中“如果”词条，不能声称这个例句已经被线上证实拒绝。

长期记忆具备实现广告效果的基础，但目前没有完成“可靠表示有条件愿望 → 新事件触发相关召回 → 确认关联后自然回应”的保障链路。本次只确认机制及限制，没有新增功能或验证该广告场景的真实模型表现。

## 6. 保留范围和历史状态

正式JAR存在聊天保留任务：按归属保留最近50轮聊天文字；音频另受72小时及数量上限约束。云端成功提取后，批次素材表会清理已处理内容。这说明长期记忆保存的是整理出的事实，而不是所有原始对话永久留在活跃历史表。

当前账号历史上有一条已完成的全量遗忘标记，多组旧素材`recall_allowed=false`。本次只读确认，不恢复、不删除、不改写；受抑制资料不能当成当前可用记忆计算，也不能因云端曾提取就宣称它仍可召回。

跨会话共享是按账号、人物和身份代次隔离的设计；本地对话恢复和事实检索另带智能体范围，云端实体以账号和人物归属为核心。同账号同人物在适用范围内跨设备共享是预期行为；不同账号不应共享。这里核查的是边界代码，未新做隔离测试。

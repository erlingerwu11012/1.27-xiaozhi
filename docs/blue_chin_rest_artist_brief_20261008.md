# 蓝发托腮半身人物：画师与Spine动画师参照表

制定日期：2026-10-08。参照用户选定的蓝发托腮、完整双手图片，沿用2026-10-03设备制作参考表；适用当前ESP32-S3、320×320屏幕及现有Spine渲染流程。本轮不改固件。

## 首版定案建议

原画1600×1800分层PSD；保持参考自然比例，不套窄长框。设备首版约200×220像素、水平居中、下缘贴底；220×240作为放大试测版。保留双手但不制作逐指动作。约40～60根骨骼、0～6个物理约束、8～15个可见Mesh，先交idle与talk_start。单张512×512图集起步。

这是制作与评审预算，不是8 FPS保证。参考图尚未绑定，不能据图认定已具备这些统计数据。硬性兼容要求与性能建议分别说明。

## 1. 项目目标与人物外观

| 项目 | 制作要求／推荐值 | 说明及验收 |
| --- | --- | --- |
| 用途 | ESP32-S3、320×320屏幕上的Spine陪伴角色 | 目标约8 FPS；按当前引擎实测确认，不要求24 FPS。 |
| 参考形象 | 采用用户选定的蓝发托腮图 | 保留蓝色短发、蓝眼睛、圆形青色发饰、白蓝外套、吊坠、微笑和托腮姿势。 |
| 双手 | 保留托腮手与下方横放的完整手 | 下方手已由AI补画，画师须核对腕部连接、拇指位置、手指数量及透视；不机械描摹错误。 |
| 画面范围 | 头顶至双前臂，不补腿部 | 左侧下方手指和右侧衣袖均须完整；不能为套尺寸截掉手。左右均指观看者视角。 |
| 风格 | 保留柔和动漫质感，优先五官辨识 | 细碎发丝可合并为大束；保留大色块和关键高光，避免缩小后只剩噪点。 |
| 背景 | 人物透明，壁纸独立 | 参考预览的黑底不是人物的一部分；不把场景、字幕、桌面或灯画入人物附件。 |
| 灯光 | 现有冷蓝主色与柔和暖边光可保留 | 作为贴图中的固定明暗，不另做大面积发光叠层；先用协调的背景检查边缘。 |

## 2. 原画尺寸与屏幕构图

| 项目 | 制作要求／推荐值 | 说明及验收 |
| --- | --- | --- |
| 分层原画 | 建议1600×1800像素PSD | 这是本人物的源稿建议，不是设备贴图尺寸。允许更高分辨率，不能拉伸参考人物。 |
| 原画留白 | 头顶、手指、袖子四周留约5%画布余量 | 先按自然比例放入画布；留白不计入人物实际宽高。 |
| 本人物比例 | 接近方形，宽约为高的0.9倍 | 来自参考图视觉估计，最终以画师原稿不透明内容及全部动作包围范围测量。 |
| 推荐首版 | 人物约200×220像素 | 保持比例，屏幕参考x=60～260、y=99～319，底部保留约1像素；此框是目标包围范围。 |
| 放大试测版 | 人物约220×240像素 | 参考x=50～270、y=79～319；接近屏幕高度3/4，面积约51.6%，不是面积3/4。 |
| 偏性能试测版 | 人物约180×198像素 | 约为首版的90%；参考x=70～250、y=121～319，不改变人体比例。 |
| 与旧表的差别 | 旧表180×240是窄半身起点，不能强套本图 | 横放前臂使轮廓更宽；本图180像素宽时自然高度约198，不会同时达到240。 |
| 脸部大小 | 首版有效脸宽争取约60～75屏幕像素 | 指脸部轮廓，不含整圈头发。以320×320、100%比例检查；不够清楚先简化细节。 |
| 安全边界 | 动作全过程不超过约220×240优先范围 | 发梢、手指、袖口按所有时刻统计；不能只检查初始姿势。 |
| 字幕 | 提供有字幕及无字幕两种320×320预览 | 字幕属界面，由设备覆盖；不可画入人物。实际字幕位置由项目方确认，不承诺顶部一定显示字幕。 |

## 3. 画师分层参照表

| 项目 | 制作要求／推荐值 | 说明及验收 |
| --- | --- | --- |
| 脸／耳／颈 | 脸底一层；颈部按遮挡需要独立；耳可与脸合并 | 补齐被刘海及手遮住的脸缘，但只需覆盖预计微小运动，勿制作完整大角度转头。 |
| 眼睛 | 左右眼可分别控制；保留眼底、虹膜／瞳孔、上眼睑／睫毛 | 第一版可用睁眼、半闭、闭眼替换图，或简单网格；保留必要的眼周皮肤，眨眼不露洞。 |
| 眉毛 | 左右各一层，或不动时画入脸底 | 只有确需轻微表情变化才独立；不为凑层数拆分。 |
| 嘴巴 | 至少闭嘴与小幅张嘴；推荐闭嘴、小开、中开3～4张 | 优先附件替换，不制作密集唇部网格；含嘴内颜色，张嘴不留下透明洞。 |
| 前发／刘海 | 按能独立摆动的3～4束拆分 | 画在同一束中的细发丝与高光不再逐根拆；前后覆盖顺序清楚。 |
| 侧发／后发 | 两侧及后发合计约3～4组 | 整个头发建议6～8个主要附件；按视觉需要调整，不是强制层数。 |
| 发饰 | 与所在发束合并，或独立静态附件 | 固定跟随该发束；不另加物理约束，不做单独漂浮光圈。 |
| 托腮手与前臂 | 手掌可与前臂合并；仅姿势需要时在袖口分开 | 整只手不做逐指骨骼；掌心贴住脸颊，轻微动画不能出现手穿脸或脱离。 |
| 下方手与前臂 | 保留完整手型；手与袖可合并或在袖口分开 | 第一版固定姿势，不挥手、不握拳；手指不拆成5条独立运动链。 |
| 躯干与衣服 | 主体合并；确有呼吸需求的局部衣袖可独立 | 衣纹、拉链、袖章优先画入对应图片；不要每个褶皱一层。 |
| 帽兜／衣领 | 按遮挡前后分1～2个部件即可 | 需要补齐发下和衣领下的图像；避免重复覆盖大面积躯干。 |
| 吊坠与绳 | 固定可画入躯干；要摆动才独立1～2层 | 亮感用贴图表现，首版不加入多层透明光晕。 |
| 总分层预算 | 争取约20～35个逻辑部件组 | 眼睛、嘴型替换图会使图片总数更多；部件组、图片文件数与同时可见附件数不是同一项。 |
| 遮挡补画 | 头发后面的脸、衣领下面的颈、袖口里的腕要补齐 | 提供分层完整稿及合成预览；位移最大时不能露透明裂缝。 |
| 图层命名 | 如face_base、hair_front_01、eye_left_open、mouth_open_small | 清楚命名、分组；左右方向在交付说明写清，不在绑定过程中反复混用。 |

## 4. Spine结构与性能预算

| 项目 | 制作要求／推荐值 | 说明及验收 |
| --- | --- | --- |
| 骨骼 | 推荐总计40～60根；初版争取≤60 | 参考旧表30～80；超过60须说明用途，不是硬件只能60根；无最低补足要求。 |
| 骨骼分配思路 | 身体／头／臂基础约10～16；头发约12～24；眼嘴控制约4～12 | 其余给必要辅助控制；只是设计起点，替换眼嘴图可以少用骨骼。 |
| 物理约束 | 推荐0～6个；初版评审线≤10 | 规则发梢摆动可手K，不必用物理；计的是约束对象数，不能把发束数当成约束数。 |
| IK约束 | 优先0；确需维持托腮接触时0～2个 | 没有大幅手臂动作时可以直接固定，避免为固定姿势增加复杂IK。 |
| Transform约束 | 优先0～4个 | 用于确实需要的跟随；少做相互依赖的多层控制。 |
| Path约束 | 首版不用 | 本图无明显必须沿路径运动的对象。 |
| 同时可见Mesh | 建议8～15个，初版≤15 | 头发及确需变形的脸／衣物使用；静态手、袖章和嘴型可以普通图片。 |
| 同时可见总顶点 | 争取300～600；初版评审线≤800 | 包括普通图片每张4个顶点；统计当前皮肤当前姿态可见附件，另外列全资源总数。 |
| 同时可见总三角形 | 争取400～900；初版评审线≤1200 | 包括普通图片每张2个三角形；顶点和三角形需同时达标，不按点数简单换算。 |
| 每个顶点权重 | 优先影响1～2根骨骼；局部最多3～4 | 清除没有视觉贡献的微小权重；不把整张脸绑定到大量头发骨骼。 |
| 网格布点 | 面部先约30～60点／Mesh，发束约8～20点／Mesh | 局部示例，仍须满足全角色总预算；只在轮廓及弯曲处增点，不能逐像素描边。 |
| 普通图片附件 | 不需要变形的部位直接使用 | 静态手有外观不代表需要额外大量骨骼；画出来和让它独立动是两回事。 |
| 透明覆盖 | 同一位置的大面积半透明叠加争取≤2～3层 | 不是整个人物只允许3层；头发保留必要边缘透明，但不要覆盖整个人物的发光面片。 |
| 下限／上限解释 | 0物理、0Mesh均可；骨骼按需要，越少不一定越好 | 所有上端不可同时用满并承诺8 FPS；本表是评审预算，非设备绝对极限。 |

## 5. 动作制作与托腮接触

| 项目 | 制作要求／推荐值 | 说明及验收 |
| --- | --- | --- |
| 必交动作 | idle与talk_start，名称大小写一致 | 手K指在Spine里设置骨骼／附件／网格关键帧，不是导出全人物逐帧视频。 |
| idle时长 | 约5～6秒自然循环 | 参考起点；首尾图像、速度衔接平稳，无突然复位。 |
| 眨眼 | 一轮待机自然眨眼1～2次；闭合再睁开约0.2～0.4秒 | 双眼协调，可用睁／半闭／闭3阶段；在约8 FPS播放下实际检查，太短可能看不到。 |
| 头发 | 仅少量刘海和发梢缓慢摆动，屏幕末端幅度先1～3像素 | 旧表2～6像素是泛用范围，这张托腮图先更小；发根与发饰稳定，避免所有发束同步甩动。 |
| 头与托腮手 | 首版头部基本固定，必要时约±0.5～1°微动 | 保持掌心与脸颊接触；不能单独让头摆动而手留原地。角度为视觉起点，不要求必须做。 |
| 呼吸 | 肩／衣服局部约0.5～1屏幕像素轻微起伏 | 首版可以不用；不移动整个人物的根骨骼带动手、脸共同上下跳。 |
| 双手 | 首版完全固定手型；下方手不动 | 保留图中的手，省掉逐指动画，不需要删掉人物外观。 |
| 吊坠 | 首版固定，或极小幅度手K | 不为吊坠添加整套绳索物理链。 |
| talk_start | 约0.8～1.5秒轻讲话嘴型循环 | 闭嘴、小开、中开轮换，不大笑、不强转头；这只是讲话表现，不承诺音素同步。 |
| 动作叠加 | idle在track0；talk_start在track1 | 当前代码讲话时循环track1；talk_start主要打嘴部键，避免覆盖全身和眨眼姿态。 |
| 动作安全 | 最极端时刻检查头发、掌脸接触、指尖、袖口及包围框 | 暂停抽查：循环起点、眼闭、发梢最偏、嘴最大；两动作同时播放也检查。 |
| 首版范围 | 先不制作挥手、握拳、大转头及大面积特效 | 后续添加必须重新检查包围范围、骨骼和实机性能；多动作存储量不等同同时播放负担。 |

## 6. 清晰度与图集导出

| 项目 | 制作要求／推荐值 | 说明及验收 |
| --- | --- | --- |
| 原画／贴图／显示 | 原画1600×1800；显示约200×220；图集512×512起步 | 三个尺寸各有用途，不能混用；图集含拆分部件，不是一整张人物按同尺寸缩放。 |
| 脸部有效贴图 | 显示脸宽约60～75时，导出脸宽先90～115像素 | 约1～1.5倍起点；不是固定强制数。检查眼、嘴清晰后按实际采样调整。 |
| 眼睛／嘴型 | 按最大屏幕显示尺寸约1～1.5倍保留内容像素 | 不得因图集空间不足先把五官大幅压缩；小部件用实际像素检查，不凭PSD放大预览。 |
| 图集页面 | 单张512×512 RGBA透明PNG，目标主像素内存1 MiB | 512×256若在不牺牲有效分辨率时能装下可用；包含解码临时内存的总峰值会更高。 |
| 避免默认升级 | 不直接默认1024×512，亦不从小贴图放大造高清 | 需要更大时先说明放不下的部件与尺寸，项目方再检查PSRAM和真机表现。 |
| 打包修剪 | 裁去部件外透明空白，紧凑打包 | 不能切掉用于补画的隐藏内容；保持图集引用和UV一致，不手工只缩PNG。 |
| 边缘设置 | 设备尺寸下约2像素间距与重复边缘填充起步 | Linear滤波；PMA、PNG与atlas声明按已跑通流程一致，不自行混用。 |
| 边缘清理 | 去除参考AI图片发丝外的杂色亮边、孤立像素和不规则残留 | 不要带黑色底边；分别在浅灰、深蓝和透明棋盘格检查。 |
| 微小细节 | 发丝可简化；吊坠和发饰保留明确轮廓与亮暗区别 | 小于一个屏幕像素的花纹无需逐条保留；优化画法不靠增加网格。 |
| 颜色 | 以设备320×320预览为准，保留脸与头发的对比 | 最终屏幕RGB565；柔和渐变细腻程度受显示限制，画师不承诺原稿所有层次完全复现。 |

## 7. 工程兼容及交付文件

| 项目 | 制作要求／推荐值 | 说明及验收 |
| --- | --- | --- |
| Spine版本 | 导出4.2.x，与项目4.2运行库匹配 | 旧项目已验证4.2.26；先交小样预检，不交4.3导出要求设备直接读取。 |
| 皮肤 | 先交default单皮肤 | 皮肤名称须与最终role.json一致；首版不附带大量未使用皮肤和道具。 |

| Spine源工程 | 可编辑.spine工程及其引用的图片文件 | 不能只交录屏／视频；保证在指定4.2编辑器中可打开并继续改动。 |
| 导出资源 | 骨骼.skel＋.atlas＋对应单张PNG；同时交JSON便于核对 | JSON和SKEL必须来自同一最终工程／版本，atlas页面名与图片文件名一致。 |
| 动作预览 | idle和讲话叠加的GIF／MP4，以及320×320静态预览 | 供审核，不替代骨骼资源；导出视频帧率不代表ESP32实机帧率。 |
| 统计单 | 骨骼、各约束、当前可见Mesh／顶点／三角形、全资源数、贴图尺寸 | 注明统计皮肤、动作和时刻；不能把所有隐藏嘴型合计当作同时可见负担。 |
| 设备上传包 | 后续由项目方按现有脚本打包spine.bin | mmap角色资源包，包含配置及骨骼、图集、PNG；不是ZIP、不是应用固件。 |
| 包体要求 | 沿用当前小于4 MiB的要求，打包时再核对分区 | 不能依据PSD、PNG或RAR大小直接判定可上传；主像素内存另算。 |

## 8. 验收顺序与责任

| 项目 | 制作要求／推荐值 | 说明及验收 |
| --- | --- | --- |
| 第一阶段：构图 | 先提交透明合成稿与200×220原生屏幕预览 | 确认五官、完整手、自然比例及贴底后再精细拆图；另给220×240对比，不能先全部绑定再改构图。 |
| 第二阶段：分层 | 检查单独显示每组、错开位置时的补画、遮挡顺序 | 没有漏底、断腕、黑边；托腮手与脸位置正确。 |
| 第三阶段：动画 | 先交idle，再交track0＋track1叠加讲话 | 两动作共同播放仍无穿帮；统计预算达标或逐项说明偏离原因。 |
| 第四阶段：上机 | 项目方静置120秒、对话120秒及拍照测试 | 查看完整30秒窗口display_fps，争取约8；没有真机测试前只说完成制作，不说保证达标。 |
| 性能排查顺序 | 先看显示包围范围与绘制耗时，再看网格／约束和贴图 | 当前引擎全部可见附件仍重画，只有眼睛动不意味着只绘制眼睛；不靠小动作保证省CPU。 |
| 内存参考 | 稳态争取PSRAM≥2 MiB、内部RAM≥16 KiB | 项目方负责采集；拍照峰值和最大连续内存另查，不作为画师单独能保证的数值。 |
| 修改方式 | 一次只调显示尺寸、图集或结构中的一项 | 保留版本和原始源稿，避免把效果变化与性能变化混在一起。 |
| 交付边界 | 画师负责绘图；动画师负责绑定和动作；项目方负责打包／上机 | 若同一人全包，也按以上阶段交付；AI示意图仅供造型参考，不是已分层角色。 |

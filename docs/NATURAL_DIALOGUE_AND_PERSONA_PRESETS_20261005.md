# 自然对话与人格模板上线记录

已发布到 https://www.realecho.cn/ ，默认官方模型为 `qwen3.8-flash`，temperature 为 0.4，关闭思考及思考保留。沿用原有官方模型配置 ID，没有增加产品 V2，也没有接入第二个润色模型。

## 用户能看到的变化

新建智能体仍然是三步。在第三步“人格设定”中，用户可以选择六套模板：自然朋友、温柔倾听、轻松幽默、理性交流、做事搭档、俏皮调侃。新建时默认自然朋友，选好后可直接编辑，也可以完全自己写。

角色配置页也提供相同模板，原先不能编辑的人格输入框现在可以编辑。仅修改人格也会进入待保存状态。用模板覆盖已有自定义文字前会提示确认。原有模组、塔罗和盲盒放在“更多生成方式”中。

平台没有批量改写已有用户人格。发布前后，所有智能体人格记录的聚合指纹一致。用户自己的性格、称呼和声音仍由用户决定。

## 对话规则和执行方式

三层结构保留：平台规则负责事实、权限、工具与表达边界；用户人格原文负责性格；本轮可信上下文负责时间和身份。工具仍通过原生 tools 传递，没有删掉工具定义或功能模块。

减少重复表达规则，加入正常成年人聊天的示例，并明确区分闲聊、建议和操作。用户说“别教育我”“不要方案”“今天别逗我”时，应当收住。计划不等于完成，尚未发货不等于已收到，工具回执没有确认完成就不能宣告成功。

人格不会使模型获得新权限，也不能覆盖设备能力。保留既有参数校验、实际能力检查、身份限制、业务回执和重复操作保护。

真实测试发现两类漏调用，已经补充执行路由：

- “替我拍一张，看看眼前这个杯子”：按明确肯定请求进入原有设备工具执行器。否定和引用表达不执行。
- “请查询东京现在的时间”：明确城市的当前时间查询进入统一 ToolManager 和真实 ServerMCPExecutor，再把工具结果交给同一个主模型回答。支持 14 个明确城市；未知地点、历史时间和有歧义的表达不会猜着执行。

上述路由沿用原有执行器和校验，不从模型正文中抽取 JSON 来执行，也不把“我查一下”“我拍一下”当作完成证据。

## 模型与网关

管理服务默认设置、设备计费策略、设备所属令牌许可和网关模型价格表同步支持新模型。普通默认服务令牌通过新增的阿里 OpenAI 兼容通道请求 Qwen3.8；旧阿里原生通道及旧模型保持可用。硬件计费继续使用专属分组、所属令牌和服务签名。

测试中的旧阿里原生通道返回 400，不能直接用于此次新模型配置。切换到兼容接口后，流式和非流式请求、实际用量结算及重复请求拒绝验证通过。

发布保留原有上下文预算。新模型输入边界及价格依据[阿里 Flash 文档](https://help.aliyun.com/zh/model-studio/qwen3-8-flash)和[Max 文档](https://help.aliyun.com/zh/model-studio/qwen3-8-max)配置；计费允许列表只开放已核实的模型、操作与地域组合。

## 验证结果

- Python：214 项回归通过，包括真实失败复现、工具校验、聊天链路、身份、提醒及 TTS 相关约定；离线回归禁止网络访问。
- Java：4 项默认设置和硬件计费策略测试通过；最终 JAR 构建通过。
- Vue：14 项挂载组件交互测试通过，覆盖选模板、自定义覆盖确认、返回步骤保留草稿、保存和重新打开；最终前端构建通过。API 使用合成夹具，没有写真实用户配置。
- 网关：模型参数、价格和请求结构测试通过；6 项真实阿里请求经候选鉴权路由、隔离账本验证通过，包括流式、聊天、摘要、习惯和重复请求防护。
- 第三轮模型验收：85 次调用，包含七种人格的新措辞对话、Max 对照及 15 个工具选择用例。原始原生工具选择为 14/15；补上明确请求路由后，真实模型提议经过实际运行时路由和校验的隔离执行结果为 15/15。
- 正式网关复验：实际统一 ToolManager → ServerMCPExecutor → 在线 MCP → 主模型回答，三个城市查询完成；另外六句日常聊天没有检出卖萌词或舞台标签。本轮这组复验共 9 次主模型请求，没有第二个润色模型。
- 指定设备 `ac:a7:04:fd:20:2c`：管理配置返回新模型和 0.4 参数。所属令牌和服务签名发起真实模型请求，回答 `391`，账单状态为 settled，用量来自上游。
- 正式域名返回 200，管理服务、对话服务和 MCP 网关运行正常。回滚镜像、源码、JAR、网站与私密配置备份保留在服务器。

## 如实保留的问题和测试范围

第一、二轮输出中的擅自给建议、错误时间推断、否定事实反转，以及第三轮漏调用均保留在测试记录中。完整工具目录下直接依赖模型 auto 选择，仍出现只承诺查询而未调用的情况；执行路由是为解决这类明确常用请求而增加的，不意味着模型原生选择已经全部可靠。

对话自然程度属于人工判断。本轮仍有少量额外建议、多余追问、轻微夸张以及不必要的认错，不能把“没有舞台标签”当作“每句都像人”。本轮采用真实输出驱动的三轮人工提示词迭代，没有训练模型权重，也没有宣称运行了 GEPA。

设备配置和签名模型请求已实测，但本轮没有重新让物理设备调整音量、亮度、拍照或创建提醒。相关工具的本轮执行测试使用隔离传输，真实只读 MCP 查询使用在线服务。前端完成组件交互及构建检查，没有登录真实用户账号进行完整浏览器验收。

不能承诺所有自然语言理解都正确。当前版本增强了常用明确请求、事实边界和正常对话，复杂请求仍需要明确参数、能力检查、必要澄清和后续失败样例回归。

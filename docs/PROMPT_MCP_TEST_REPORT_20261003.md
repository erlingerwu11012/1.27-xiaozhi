# 精简提示词与 MCP 测试结果

日期：2026-10-03。通过 SSH 在 121.40.239.140 的独立临时目录测试。没有修改线上提示词、业务代码或服务配置，没有创建真实提醒/习惯，没有操控在线设备。

## 结论

**精简提示词仍能调用 MCP；目前这版不能直接上线。** 工具定义由请求的 `tools` 字段提供，并不需要全部写在 system 提示词中。但是，工具定义和跨工具选择规则不能一起省略。真实模型存在“正文假装调用”和能力缺失时错误选工具的问题，单靠加强提示词仍不能保证可靠执行。

## 实际测试范围

- 使用服务器当前配置的 `qwen-plus` 与真实模型接口，temperature=0.7；共45次模型请求。人格原样保留。
- 当前配置的服务端 MCP 完成初始化和真实 tools/list，返回 random_decision、habit_create、habit_list_manual、add_reminder、get_world_time 五个工具。
- 将精简版模型选择的 get_world_time、Asia/Tokyo 参数交给真实 MCP 执行；isError=false。真实回执再交给模型，模型正确转述回执中的03:04为“三点零四分”。这是实际模型选择→真实工具执行→最终回答的验证。未独立校验服务器时钟。
- 音量、亮度、状态、拍照、便签等设备工具使用仓库定义和能力夹具；执行传输为模拟 WebSocket。没有获取在线设备完整工具快照，不能据此断言某块硬件支持预览或已实际执行操作。
- 习惯和提醒只验证模型工具选择及参数，没有向真实工具提交写入；错误提醒回执使用合成数据。

## 据此调整方案

1. **保留真实工具目录和参数schema。** 每轮依据当前会话能力提供，名称、参数和执行链路保持同步。
2. **保留功能专用模块。** 摄像头开/关/拍照区别、提醒与便签的选择、当前提醒卡片动作等不能靠通用一句话代替。未验证完整迁移前保留原规则。
3. **操作结果有执行证据才允许说完成。** 现有目录白名单和错误回执机制继续使用；补充意图与工具匹配、操作未调用时的失败处理。明确控制请求可使用可靠路由或受约束的工具选择，而不能依赖模型在正文承诺执行。
4. **能力缺失直接说明。** 即使模型输出不存在的工具，也必须在执行前拦截；不能把拍照作为预览的替代。
5. **风格单独评测。** 本次人格没有改动，仍出现夸张调侃、虚构共同经历、未授权语音标签。工具测试通过不等于自然对话达标。需要平台约束人格只影响表达，不改变事实、参数或执行状态，再用独立对话样本验证。

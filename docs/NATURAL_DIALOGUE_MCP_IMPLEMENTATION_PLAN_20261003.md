## 目标与范围

让用户用日常说法交流：意思明确时直接处理；能承接上下文和纠正；缺少必要信息时只补问关键的一句。操作结果依据真实执行回执，避免正文假装调用、错误替代工具和重复执行。

本期优先覆盖音量、亮度、设备状态、摄像头预览/拍照、一次性提醒、无定时便签及其多任务组合。每项能力必须以真实设备和当前服务端工具目录为准；没有预览能力的设备必须能正确说明不支持，不为了完成验收伪造预览工具。

用户人格原文、名字和昵称、三步创建方式、模型和音色保持不变。不恢复二次语音润色，不新增一个常驻的意图分类模型。普通聊天继续由现有主模型生成；现有主模型的工具回执续接属于执行流程，不是二次润色。

本期不替换现有框架，不增加另一套提醒业务逻辑，不批量删除工具，不修改固件以补出不存在的能力。其他 MCP 和主动设备事件保留既有功能，并纳入兼容回归；严格受控操作的承诺范围以已完成适配和验收的能力为准。

这是实现与验收目标，不承诺所有自然语言都被一次理解正确。有限测试集通过，也不能等同于所有场景准确率。

## 阶段一：核实能力，建立公平测试基线

工作：

1. 在隔离测试环境固定服务器代码、提示词、人格、模型参数、上下文及工具目录快照。对照与候选使用相同输入和能力，记录真实完成、未运行和测试基础设施错误。
2. 检查从模型请求、当前网关、响应适配器到工具管理器的调用字段是否完整保留。原生调用、正式适配器解析出的协议调用与普通正文严格区分；自然语言“已调用”不是协议。
3. 获取测试设备当前会话的真实工具目录，并在执行前再次检查当前连接、目录版本和工具可用性；仓库夹具不作为在线硬件能力证据。
4. 为本期能力登记用途、参数范围、前置条件、接收人来源和成功条件，明确开预览/关预览/拍照、提醒/便签的区别。
5. 建立至少100个不重复的中文文本用例，覆盖直接表达、口语改述、否定、引用、假设、歧义、多轮、省略、纠正、取消、多任务和能力缺失。自然说法留出部分只做验收，不参与规则调试；每项明确操作同时配无操作的反例。

交付：能力与回执契约清单、固定测试快照、用例与预期结果、当前版本基线报告。

验收：能分别定位语音识别、语言理解、工具选择、参数、执行、回执、播报层面的错误；不能用总成功率掩盖关键错误。现有旧脚本的失败逐项区分环境/夹具问题与真实缺陷，修正夹具不得削弱生产检查或删除失败断言。

## 阶段二：先解决假调用、错误替代和假成功

工作：

1. 对完整、明确且属于已适配能力的操作建立待执行任务。常用表达可快速匹配；复杂说法由现有主模型结合上下文理解。快速匹配检查动作、对象和否定，不能只因包含“摄像头”“关掉”就执行或退出会话。
2. 在统一执行入口校验实际能力、参数和用途关系；不将模型自报置信度当作可靠依据。缺少预览能力直接返回不支持，不调用拍照、浏览器等替代能力。
3. 已确认的操作没有正式工具调用时，缓存并阻止其完成话术进入字幕/TTS。仅在未发出操作且意图完整时允许最多一次受约束的主模型调用修复；依然失败就明确说明本次未执行。人格不参与这一判断。
4. 统一记录任务ID、会话/本轮ID、目录版本、参数版本、调用ID、真实回执和状态：待补充、待执行、已发送、已接受、成功、失败、结果未确认、取消。多任务分别记账。
5. MCP正常返回不自动等于业务完成。“已接受”只报告已接受或正在处理；超时/断线归为结果未确认，禁止自动重试可能已产生副作用的操作。新提醒等创建操作仅在明确支持幂等标识或确认未发出时才能安全重试。
6. 在既有缓存首轮、工具结果直回复、模型续接和字幕/TTS入口统一执行结果规则。受控操作的状态、数值和关键对象由程序依据回执生成简短自然反馈；该操作反馈不再交给模型自由改写完成状态。普通聊天保持现有表达能力。

交付：能力检查适配、任务/调用状态记录、缺少调用的处理、受控结果播报路径及故障用例。

验收：本期契约与故障用例中，正文假调用导致执行为0，缺少能力的错误替代执行为0，无成功回执的完成播报为0。包含超时后的迟到回执、重复回执、断线重连、陈旧连接、模型正文先于工具字段返回、成功与失败混合任务。工具结果成功条件不足时，允许降级说明未确认，不允许猜成功。

## 阶段三：实现接话、补问、纠正与取消

工作：

1. 为当前任务保存动作、目标、已有参数、缺失项、来源轮次、当前状态；按可信说话人和会话隔离。未知身份不得猜接收人，不从用户文本字段采信人员ID。
2. 补问只针对缺失或冲突的信息，不重新确认已明确的全部请求，也不要求用户重新说完整句子。
3. 对“关了吧”“再小一点”等指代，结合最近相关任务、话题变化、当前对象和实际状态判断。存在多个合理对象时澄清；过期任务不默认为当前指代。
4. 明确纠正只更新尚未发送的本次任务参数，不能静默修改已创建的提醒。操作已成功后再说“改成十点”，需找到对应事项并确认实际存在修改能力；否则说明限制并选择合法流程。
5. 用户取消待执行任务时直接终止。对于已发送的操作，只有可用取消工具和真实取消回执才能说已取消；缺少取消能力时说明当前状态。
6. 切换话题、换人、断线、任务超时或服务重启时清除/过期待确认状态，不自动执行遗留任务；已发送操作的账本与待确认信息分开处理。

交付：短期任务状态、参数补全、指代/纠正/取消规则及多轮测试。复用既有存储或会话机制，具体持久化方案在阶段一核实后确定。

验收示例：

- “明天上午九点提醒我喝水”信息完整，直接进入执行。
- “明天提醒我喝水”只问时间；回答“九点”后承接该任务。
- 在尚未提交的时间确认中说“不是九点，是十点”，更新为十点且只创建一次。
- 最近明确讨论摄像头后说“关了吧”，按可用能力关闭；音乐和摄像头都可能是目标时只问目标。
- “不要打开摄像头，我只是问预览是什么”不执行摄像头操作。
- 换一个说话人、切换话题后，不继承不相关的待执行事项。

这些例子用于明确预期，并非限定用户只能使用这些说法。

## 阶段四：优化平台提示词，保留用户人格

工作：

1. 在阶段二、三的机制通过后，再完善三层提示词：平台规则、原样用户人格、可信会话资料。用户三步创建界面及保存的人格不重写。
2. 删除平台额外添加的幼态话术示例、强制填充词、每轮追问和无必要的角色表演引导。用户自己配置的表达习惯继续有效；平台不统一要求所有人格成熟、温柔或禁止卖萌。
3. 保留工具目录与参数schema，按实际可用能力附加功能模块；跨工具选择规则迁移完成并验收后，才移除旧system中的重复项。先不以工具路由的词法分数删除不熟悉表达所需的工具。
4. 保留提醒接收人解析、当前卡片与历史便签区别、摄像头用途、身份、记忆和主动设备事件规则。普通对话、工具回调、出现问候、晨间待办等入口都检查模块覆盖。
5. 保留官方语音标签白名单、动作限制、播报长度和emoji过滤；未授权标签由既有编译/过滤流程处理，不靠第二个模型修饰。人格表达不改变事实、时间、参数和操作状态。
6. 天气、时间和说话人资料按本轮来源提供；确认所有入口覆盖后才去掉旧快照。统计system、tools、历史和动态资料的总token，不把规则换位置当作实际成本下降。

交付：完整可装配的提示词候选、模块对应清单、现状差异说明、工具与对话对照结果。

验收：测试前后用户人格原文一致；工具功能回归通过；没有强制每轮追问或平台固定口癖；不同用户人格仍有差异。普通聊天的质量单独人工评估，不能把工具选择通过当作自然对话通过。

## 阶段五：统一验收、单设备试运行与回滚

工作：

1. 先运行离线契约、协议、状态、字幕/TTS及兼容回归，再在固定目录和参数下比较真实模型。保留失败记录和未运行原因，不把错误判定修复算成模型能力提升。
2. 全部100个以上文本用例至少运行一次；工具缺失、否定、纠正、假调用及已有失败案例至少3次。预设模型请求次数、token/额度上限；触达保护时标记未完成，不当作模型失败，也不悄悄扩大预算。
3. 语言理解与对话目标为留出集语义正确率至少95%，包含正确澄清；这是初始上线门槛，尚未达到，也不代表所有语言准确。针对核心失败用例逐项通过，硬约束在测试中必须100%通过。单独报告误操作、漏操作、澄清是否必要、事实/参数、完成状态和延迟。
4. 实际语音验收至少20段，覆盖不同日常说法和多轮接话，分别记录原话、ASR文本、理解结果和操作回执。语言模型测试通过不代替语音识别测试。
5. 在明确指定的测试设备先执行可恢复操作，再验证一条可清理的提醒/便签，结束时恢复音量/亮度及预览状态并清理测试记录。设备和测试事项在部署阶段确定，当前不操控线上硬件。
6. 保留普通聊天流式输出。对操作反馈增加的等待，记录首个真实反馈和完整操作的p50/p95。暂定普通聊天p95相对基线新增延迟不超过300ms；执行等待和澄清分别说明，不人为抢先播报完成。该数值是待测的工程目标。
7. 新机制采用默认关闭的独立开关和设备范围；先shadow记录计划与决策，不增加真实调用、不替换用户播报，再对测试设备启用完整执行链路。通过后扩大范围。
8. 每阶段独立提交并记录代码SHA、非敏感配置、测试报告和开关值。上线前重新核实是否有其他工作区的新提交，不覆盖并行改动。回滚优先关闭本次开关、恢复本次提示词和模块配置，保留原有会话、身份及出站守卫；不对生产仓库执行破坏性重置，也不删除用户数据。

交付：完整验收报告、真实设备结果、试运行范围、发布记录和回滚步骤。

上线条件：语义与硬约束门槛通过；现有身份、提醒、记忆、多工具和语音管线回归通过；旧失败有明确结论；真实设备能力与结果核实完成。任何测试样本出现假成功、错误对象写入、错误能力替代或重复创建，暂停扩大范围，定位后复测。

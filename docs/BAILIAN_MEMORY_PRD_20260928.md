# 百炼长期记忆与统一用户管理产品需求书

版本：V1.2（2026-09-30 本地续接、累计门槛和存档保留规则修订）  
日期：2026-09-28  
对象：智控台、对话服务、人物与生物识别服务、设备固件  
初版范围：源码核查、需求定稿及问题清单。后续开发、发布和未验收项以《BAILIAN_MEMORY_IMPLEMENTATION_20260929.md》及《CONTEXT_MEMORY_IMPLEMENTATION_20260929.md》为准。

## 1. 产品结论

可以实现。需要把“谁正在说话”“记录属于谁”“是否开启长期记忆”贯通到服务端、智控台和固件，不能只接一个阿里接口。

最终体验是：账号下的爸爸、妈妈、孩子各有一条成员档案；人脸和声纹都在智控台“用户管理”中绑定。声纹识别确定每轮说话的人，长期记忆和习惯分析分别使用这个人的材料。人脸主要保留主动唤醒作用，不替代本轮声纹认人。

只有当前智能体在智控台选择“长期记忆”，才使用百炼。选“本地短期记忆”时，继续原有短期上下文与习惯副模型，不调用百炼增强聊天或习惯分析。

### 1.1 已确认的产品规则

| 项目 | 正式要求 |
| --- | --- |
| 成员管理 | 在“用户管理”统一显示昵称、人脸绑定、声纹绑定，并完成采集、绑定、重录、解绑操作 |
| 人物ID | 系统生成，账号下稳定保存；用户不填写、不需要看到技术ID |
| 同账号多人 | 各自记忆；不建立账号公共长期记忆 |
| 认人依据 | 以本轮声纹识别为准；人脸、昵称、上一轮说话者均不能替代 |
| 没有任何有效声纹绑定 | 使用该账号的默认用户及本地短期记忆；即使智能体选择长期记忆，也不调用百炼写入或检索；只有人脸也按此规则 |
| 已绑定声纹但本轮未识别 | 正常聊天，静默跳过长期记忆读写，不转默认、不沿用上一人 |
| 首次成功绑定声纹 | 删除旧默认用户及其记忆、画像、行为材料、习惯、备忘提醒、闹钟；真实成员资料独立保留 |
| 所有有效声纹后来都被解绑或删除 | 建立新的空白默认用户、空白默认记忆；不恢复旧数据 |
| 云端写入 | 每天北京时间03:00检查；每位已绑定且识别成功的声纹成员累计至少10,000个用户原话估算token后提交，不足跨日保留；默认和未知身份不上传 |
| 习惯分析副模型 | 保留，并补齐逐条记录的人物归属 |
| 检索 | 主对话模型通过 function calling 按需发起，服务端控制身份和调用预算 |
| 画像 | 生产保持关闭，待单人物真实删除及存储计数口径验证后再启用；不做用户画像查看页 |
| 重录声纹、换设备 | 复用原成员ID；重录在原声纹记录上更新；同账号设备共用授权模板 |
| 昵称重复 | 同账号新建或改名重复时拒绝，提示“昵称已重复” |
| 工作日 | 周一至周五；周末不触发，不接入法定节假日及调休表 |
| 展示范围 | 用户看到成员昵称和绑定状态；记忆、画像、习惯分析及同步状态在后台运行 |
| 引导 | 不在代码中添加录声纹引导、默认删除宣传提示、未认人播报；由营销及说明书承担 |
| 交互渠道 | 设备语音，不新增纯文字聊天 |
| 当天跨设备更新 | 接受每日上传带来的延迟，不增加即时跨设备同步保证 |

事实写入、检索默认Lite；画像保持关闭。以下新增规则优先于后文初版建议与旧预算示例。

### 1.1.1 本地短期记忆与累计抽取（2026-09-30确认）

- 可信人物在相同账号、人物、默认代次及智能体范围内，跨唤醒恢复最近50个完整文字轮次；未知身份只维持当前连接临时上下文。
- 文本存档最多保留50轮；用户录音最多保留72小时且最多最近50条，先达到哪个就清理哪个。助手音频仅用于播报，不长期存档。未识别录音仍可在保留期间作为声纹注册素材。
- 本地上传队列独立于上述存档：低于10,000个用户原话估算token，完整原文跨日保留，不因录音或50轮清理丢弃。助手原文和真实工具结果随对应用户原话上传，但不计入触发门槛。
- 固定窗口为北京时间03:00至次日03:00；当日达到门槛不即时调用，次日03:00检查。一次任务可以处理多个成员，每人独立Add；没有符合条件材料不调用、不产生Add费用。
- 单人全部原文按角色、轮次、智能体和时间顺序序列化到一个messages文本中，目标一次Add。只有异步抽取确认成功才清除对应水位内的队列副本；结果未知或失败保留。原存档按自己的保留规则清理。
- 本地优先按需检索；有可靠原话或业务证据时返回，本地不足且是已绑定声纹的长期模式成员才查询百炼。默认与未知身份均零百炼写入和检索。
- 压缩继续使用16万准备、18万提交、20万保护、约5万目标；压缩不触发Add、不删除存档或待上传原文。断连不再额外调用一次摘要模型，仅保存已经验证的压缩摘要。
- 音频过期、人物退役、更正和忘记不能通过迟到上报、旧摘要或缓存复活。旧无可信归属记录不猜测人物。

本次实施、实际费用与待实机项见《MEMORY_CONTINUITY_IMPLEMENTATION_20260930.md》。

### 1.2 模块分工

| 模块 | 负责的事 |
| --- | --- |
| 统一人物服务 | 账号权限、成员ID、昵称、模板关联、默认用户生命周期 |
| 声纹服务 | 比对音频并返回候选模板；由人物服务验证是否属于本账号有效成员 |
| 主对话模型 | 理解问题、选择记忆检索工具、根据背景回答 |
| 习惯副模型 | 根据该人的近期行为证据判断规律，提出习惯规则 |
| 百炼记忆库 | 托管长期事实、抽取画像、语义召回；Pro Search额外进行Rerank |
| 业务规则与设备 | 保存准确的习惯、提醒、闹钟状态并执行；记忆文本不负责定时触发 |

## 2. 智控台记忆开关

### 2.1 复用现有选择

当前唤醒向导有“本地短期记忆”和“Mem0AI记忆”两项，底层分别为 Memory_mem_local_short 和 Memory_mem0。正式产品保留两种用户选择，将长期项明确显示为“长期记忆”，接入百炼实现。

建议新增 Memory_bailian 模型配置和对应 provider，避免直接把原 Mem0 参数当作百炼参数。同步修改唤醒向导、角色配置、选项加载白名单、后台模型初始化和配置下发；旧长期项怎样映射须在迁移中明确，不能出现页面选择长期但服务端仍调用 Mem0，或新选项被白名单自动改回短期。

开关以当前智能体的服务端配置为准；同账号不同智能体可分别选择。声纹与人物目录仍按账号共享，不因记忆开关变化重建成员ID。

### 2.2 两道判断

| 当前配置 | 账号声纹状态 | 本轮结果 | 百炼行为 |
| --- | --- | --- | --- |
| 本地短期记忆 | 任意 | 任意 | 不进行聊天Search、Add、画像读取/抽取、习惯历史增强 |
| 长期记忆 | 权威确认零有效绑定 | 有效用户语音 | 使用当前一代默认用户的本地短期摘要及近期记录；百炼 Add、Search 和画像调用均为零 |
| 长期记忆 | 至少一位有效绑定成员 | 本轮识别出有效成员 | 只使用该成员实体 |
| 长期记忆 | 至少一位有效绑定成员 | 未识别、识别失败、模板未关联成员 | 静默跳过长期读写 |
| 长期记忆 | 绑定状态无法确认或目录已过期 | 任意 | 暂停长期读写，不能把故障当作“零绑定” |
| 长期记忆 | 任意 | 唤醒文本、主动问候、维护消息等无本轮用户语音 | 不据此创建个人记忆或认领上一人的身份 |

关闭长期选项后停止该智能体新增读写，停用其长期背景注入，取消尚未提交的普通上传材料。再次开启只处理开启期间的新材料，不追补关闭期间的对话。已有云端数据默认保留，仍可能计存储费；必要的数据删除任务继续完成，不受普通开关和费用阈值阻断。

短期模式下原习惯分析及明确提醒仍可工作，但不向百炼送材料。多人情况下短期对话历史、摘要和工具上下文也需隔离，避免通过旧摘要绕过个人长期记忆的隔离。

## 3. 统一用户管理与稳定身份

### 3.1 用户看见的页面

复用当前 UnifiedUserManagement.vue 及 /user-identities 接口，在此基础上完成一体化操作。当前页面只能绑定已录好的资料、仍要求手填user_id，并另外保留人脸和声纹页面，不满足本需求。

每一行或成员卡显示：

| 昵称 | 人脸 | 声纹 | 相关操作 |
| --- | --- | --- | --- |
| 爸爸 | 已绑定/未绑定 | 已绑定/未绑定 | 修改昵称、绑定人脸、绑定或重录声纹、解除对应绑定 |

要求：

- 创建成员只填写昵称，系统生成ID。人脸先录、声纹先录均可；给已有成员补另一种资料时直接在该成员上操作。
- 人脸采集和声纹录音在“用户管理”发起并完成，不要求先去另一个页面创建一份资料再手工拼接。
- 普通用户入口统一到“用户管理”；旧“人脸管理”“声纹识别”入口重定向或作为内部复用组件，不继续形成三套互相独立的人员档案。
- 不展示user_id、face_profile_id、speaker_id等技术字段，不展示事实、画像、分析日志、费用或云端删除进度。
- 绑定结果成功或失败按真实结果反馈；不增加“建议尽早录声纹”等营销提示。
- 此处的“用户管理”是账号内家庭成员管理，不是平台管理员的登录账号管理。删除默认用户或家庭成员均不能删除产品登录账号。

### 3.2 ID与模板的关系

一个成员对应一个稳定person_id，下面关联人脸资料ID、声纹模板ID。技术存储可以保留各服务原有ID，通过映射统一，不能仅靠昵称同名合并。

新增人物ID建议采用服务端生成的usr_前缀随机ID，适配现有人脸接口和固件部分校验；已有有效ID保持不变，并统一修正固件对旧稳定ID的识别。不能为“统一格式”重新分配已建立记忆的成员ID。

创建真实成员可以早于声纹绑定。例如先给“爸爸”录人脸，已生成成员ID，但没有声纹时仍不能认领爸爸的个人记忆；账号整体没有声纹则继续默认模式。随后在“爸爸”卡上绑定声纹，复用已有ID。

默认用户是系统临时身份，不是爸爸、不是登录账号，不允许在新界面把人脸或声纹直接绑定到默认用户。真实成员和默认实体分开，防止首次绑定时删除真实成员。

### 3.3 昵称唯一

- 同账号按统一规范比较昵称，至少去掉首尾空白；同账号成员不能有重复昵称。
- 新建、改名、导入及旧入口都须校验；数据库建立对应的账号内唯一约束，防并发重复提交。
- 编辑当前“爸爸”仍使用“爸爸”允许通过；新建第二个“爸爸”或把“孩子”改为“爸爸”返回“昵称已重复”。
- 不同账号可以各有“爸爸”；不自动改名为“爸爸1”，不按同名认定同一人。
- canonical昵称在统一人物表维护，关联人脸/声纹页面显示同一名称。模型提取的称呼偏好不能擅自改管理昵称。
- 旧数据已有重复昵称时，保留不同成员ID和记忆归属；解决昵称冲突后再启用唯一约束，不能合并其记忆。

### 3.4 跨设备与声纹重录

- 同账号设备获取该账号全部有效绑定的声纹候选及人物映射；录音来源agent_id/device_id只表示采集来源，不能限定其他设备是否识别该成员。
- 每次识别及配置下发显式验证账号权限；不同账号不能共享候选模板或成员目录。
- 换设备无需重新建成员或重新录声纹；云端历史沿用原账号+成员实体。
- “重录声纹”更新原记录，保留person_id、声纹逻辑记录ID、记忆、习惯和业务归属。
- 更新先准备可用的新模板，再原子切换；新模板失败保持旧模板可用，不能只回滚数据库却把旧声纹向量丢掉。
- 增量通知在线设备刷新配置；离线设备重连获取最新版本。不能只更新网页列表。
- “解除声纹绑定”与“删除成员”不同。解绑停止该模板用于人物识别，保留原人物ID；重新在原成员上绑定可延续原记忆。未绑定的历史向量不能计作有效候选，也不能识别出幽灵成员。
- 所有有效绑定消失后按第4节建立空白默认用户；原成员的个人资料不自动合并到默认。明确删除成员才清理该成员资料，云端删除能力受第8.3节约束。

## 4. 默认用户切换与数据删除

### 4.1 状态转换

| 事件 | 人物与记忆状态 |
| --- | --- |
| 账号零有效声纹绑定 | 存在一位系统默认用户；仅使用本地短期记忆，不建立新的百炼默认实体 |
| 首位成员声纹绑定真实成功 | 进入个人模式；删除旧默认用户及指定数据；首位新成员记忆从空白开始 |
| 后续成员绑定 | 增加独立个人实体，不清理其他人的资料 |
| 剩余声纹仍有有效绑定 | 保持个人模式，无默认用户 |
| 最后一条有效声纹解绑或删除 | 新建一代空白默认用户与本地短期记忆；旧默认和个人内容不合并 |
| 重新绑定原成员 | 延续原成员ID；清理这一代默认用户与默认数据 |

声纹上传成功不等于绑定成功。必须完成模板注册、账号归属、人物映射与权威目录更新，才能提交零到非零的切换；失败和重试不错误触发删除。并发绑定须幂等，只清理一次旧默认实体。

### 4.2 首次绑定的清理范围

清理旧默认身份明确拥有的：

1. 默认用户档案、服务端映射、固件身份目录及身份上下文缓存。
2. 默认事实记忆、默认画像、本地更正覆盖值、检索缓存、摘要和相关对话材料。
3. 未提交的上传正文、待分析行为、默认习惯分析材料。
4. 默认用户创建或接收的旧习惯、备忘提醒、闹钟及其待投递实例、延后状态和执行队列。
5. 已提交但未结束的默认云端抽取任务及其迟到结果。

旧记录不得迁给首位成员，不做默认记忆备份、恢复选择或用户确认迁移界面。清理其他真实成员、其他账号及平台登录账号不属于本次操作。

旧owner="default"、recipient="all"等是历史业务标记，不能当作要删除的登录账号或具体人物ID。迁移时对设备账号内的历史默认业务记录明确建立归属；确属原默认范围的一并清理，其他成员创建的记录不误删。

### 4.3 人脸资料与默认身份分离

新流程中，人脸只绑定真实成员，默认临时用户不挂人脸。

旧代码允许默认主人绑定人脸，迁移需先把这类生物识别资料归入独立真实成员，再清理旧默认身份；不迁移其默认记忆和旧业务记录。旧人脸与声纹没有已验证人物映射时，由用户在统一管理中选择归属，不能仅凭同名或“第一个录声纹”自动配成同一人。存在歧义的资料先标为未归属，不参与个人认人。

默认用户删除不能依赖人脸模板计数：有人脸但零声纹仍为默认模式；有声纹但无人脸仍为个人模式。人脸快照、声纹绑定状态是两个独立事实。

### 4.4 多端和云端一致性

- 切换提交后，本地立即停用并清理旧默认内容；在线设备更新身份目录并停止旧提醒，离线设备重连先应用清理指令再恢复业务。
- 默认重建使用新人物ID/新实体代次，不能复用旧云端user_id。旧删除任务只针对旧代，不影响新默认用户。
- 所有ensure-owner、身份快照、初始化与列表接口必须服从统一状态机；个人模式下不得自行创建默认主人。
- 固件删除需贯通IdentityManager、UserContext、FaceRoster、规则存储及ReminderCoordinator。只调用RemoveUser不足以完成本需求。
- 云端删除依每日窗口执行，旧实体从切换提交时起即不可读写。仅保留最小删除任务ID、事件ID和状态用于补偿，不留可恢复正文。
- 对已提交异步任务先追踪最终状态再清理新增残留；失败、超时、服务重启后持续补偿。实际删除未完成不能记为“已完成”。
- 人脸身份快照契约允许个人模式的default_owner_person_id为空，并下发memory_identity_mode、有效声纹绑定数、目录版本及当前默认代次。缺省/故障不是零绑定。
- 普通用户不展示这一内部流程；运维侧记录真实完成状态。

## 5. 每轮认人与上下文隔离

### 5.1 当前声纹触发逻辑

服务端有效音频结束后进入ASRProviderBase.handle_voice_stop；启用声纹时使用该段音频识别，ASR和声纹任务并行。已核对流式最终文本仍调用通用路径。因此正常有效语音不是只在首次唤醒认人，而是每段结束后可识别一次。

这不等于全天持续请求。短音频、空音频、取消轮次、超时轮次不能保证识别；普通非流式路径还有音频帧数门槛。设备唤醒文本、系统维护和主动问候没有本轮用户音频时，不能借用残留身份。

本轮未重新做速度或准确率测试，不能用“很快”代替身份可靠性验收。

### 5.2 必须补齐的身份协议

本轮冻结的身份上下文至少包括：可信account_id、device_id、agent_id、turn_id、session/listen_generation、voiceprint_id、person_id、匹配状态及必要置信字段、目录版本、当前默认代次。

处理顺序：

1. 新一轮开始清空旧声纹身份；音频、ASR和声纹结果关联同一turn_id。
2. 用当前有效模板候选识别，验证匹配阈值、账号、成员有效状态和映射。
3. 冻结本轮actor与memory_entity，后续主模型、工具、日志、上传队列均使用该快照。
4. 声纹失败或人物映射失败时发出显式未知状态，服务端与固件都清空旧说话者。
5. 工具回调只能沿用发起它的有效轮次快照；异步迟到结果不能覆盖新一轮身份。

不能以镜头中的人、昵称相同、连接的current_speaker残留值、最后一个说话的人或提醒收件人代替真实本轮说话者。创建者与收件人分别记录，不能把“爸爸提醒孩子”的创建行为算成孩子说的。

### 5.3 存取隔离

- 百炼user_id采用固定的账号+person_id映射；服务端生成，模型和客户端不能任意指定。
- 事实、画像、本地摘要、查询缓存、上传队列、行为日志、习惯输入与工具授权使用同一归属。
- 切换成员时不把上一人的对话历史和工具结果带入下一人的模型上下文。长期关闭时也须防止短期摘要串人。
- 无法确认身份的个人模式对话使用临时上下文，不进入任何成员的长期材料和个人习惯统计；身份恢复后不把此前未知片段追认给该人。
- 模型连续function calling复用原轮次快照；不能随连接上的身份更新改为另一位成员。
- 声纹识别存在误识别风险，无法承诺百分之百认人。第一版须检验相似声线、儿童、噪声、短句和录音回放情况下的身份处理；不能因检索成功就判定身份正确。

## 6. 事实记忆与每日集中写入

### 6.1 保存什么

| 内容 | 处理 |
| --- | --- |
| “我平时咖啡不加糖” | 作为偏好候选，归本轮实体 |
| “下周六我要去杭州” | 保存事件及时间依据，供后续询问 |
| “我不再晚上跑步了” | 本地立即覆盖旧偏好，夜间同步更正 |
| “孩子喜欢草莓”由爸爸说出 | 记录“爸爸提到孩子喜欢草莓”，不直接写孩子实体 |
| 玩笑、假设、引用、否定句 | 保留完整语义；不能提取为已确认的本人事实 |
| 模型编造、例子、系统提示、声纹失败片段 | 不作为个人事实 |
| “已设置工作日提醒” | 只有业务工具真实成功才生成状态说明；精确规则保存在业务库 |

助手回复不是独立事实证据。用户原话、时间、业务执行结果必须可追踪；提醒取消、暂停和改期以准确业务状态优先，不能靠旧记忆文本恢复已取消规则。

### 6.2 每日任务

建议统一使用账号时区，第一版Asia/Shanghai，每日03:00开始错峰处理；时间可配置，不把设备每次断连当作上传时机。

- 长期开启期间的有效轮次先进入持久化待处理队列，按账号、实体、日期和配置版本分组。
- 默认与成员、不同成员均分别提交，禁止为了便宜混成同一个请求。
- 无新增有效材料则跳过；没有新的画像信息则不必每日抽取画像。
- 日内可合并去重，但不能破坏否定、先后变化、说话者和真实业务状态。
- 每日集中不保证每天仅一次HTTP：多个成员、材料超限、不同规则和必要补偿仍可能分批。
- 单次上下文容量以实际API契约核验；客服未给出统一窗口上限，不能推导为无限上传。中文、英文文档的消息/长度约束可能不同，开发先核实并设分批预算。
- 优先使用异步Add并持久化event_id，提交成功与抽取成功分开。结果未知时先查事件，不盲目重复收费请求。
- 单机或多进程运行需有互斥任务/租约、水位和幂等记录，避免服务器重启或多个连接重复上传同一材料。
- 写入策略按项目规则配置，Search策略独立传参；不要把Search的plan_version直接误当Add抽取策略。

messages用于抽取对话；custom_content适合保存服务端确认的简短事实或成功业务说明。画像需传profile_schema；不能把工具消息直接当作画像证据。具体契约见[添加记忆](https://help.aliyun.com/zh/model-studio/memory/add-memory)。

### 6.3 当天更正、忘记与关闭

用户语音更正或要求忘记时，在有效身份下立即建立本地覆盖/抑制规则，同时删除对应待上传旧正文；夜间执行云端更正或删除。此后检索结果注入前检查抑制规则，不能把旧云端信息重新塞回回答。

同一设备当前有效身份的正常短期上下文可以延续，跨设备当天未同步的信息允许暂时不可用。不为了这种情况新增即时云端写入或即时跨设备缓存保证。

不新增记忆浏览器、清单页或同步进度页。不能在未知身份下声称“已保存你的长期记忆”；正常回答即可，不播报未识别或录声纹引导。

## 7. 按需检索：由主模型function calling决定

### 7.1 通俗说明

设备先认出这一轮是谁。主对话模型听到问题后，判断是否需要查询这个人的旧信息：需要时调用后台“查记忆”工具；不需要时直接回答。认人和查记忆是两件事，声纹识别每段触发并不意味着每段都收费Search。

第一版采用现有主模型的工具调用能力，不增加每轮专门判断记忆的副模型。现有习惯分析副模型继续负责规律分析。

### 7.2 具体调用流程

1. 服务端读取当前智能体记忆选择和本轮冻结身份，决定是否向主模型提供memory_search工具。
2. 有可用身份时，注入少量同人画像缓存和本轮已知业务状态；不因此每轮请求云端画像或Search。
3. 主模型在当前对话不足以回答个人历史问题时，调用memory_search，参数只含query等查询内容。
4. 服务端绑定正确的user_id、memory_library_id及项目范围；模型不能选其他人的ID或账号。
5. 先查同人、同语义范围的短时缓存；未命中才请求百炼，明确传plan_version="lite"或配置版本。
6. 过滤被删除、被本地新信息覆盖和不属于当前实体的结果，控制条数与上下文长度。
7. 工具返回真实结果；主模型结合用户当前信息回答。没查到时不编造“你以前说过”。

该工具为服务端内部工具，不作为设备操作卡、记忆状态面板或身份提示播报。缓存键至少含账号、实体、代次、查询与规则版本；更正、删除、换人和模式切换使相关缓存失效。

### 7.3 主模型何时用工具

| 用户场景 | 默认行为 |
| --- | --- |
| “我上次说周末准备去哪？” | 当前上下文不足时Search自己的历史事件 |
| “按我以前说的口味推荐晚饭” | 先用同人画像；仍需细节时Search |
| “把这句话翻译成英文” | 不查个人历史 |
| “今天几号”“调小音量”“讲个笑话” | 使用对应能力，不因这些话自动Search |
| “我刚才说什么？” | 当前同人上下文足够时不Search |
| “我有哪些闹钟？”“取消早上那个提醒” | 查准确业务工具，不用语义Search代替规则列表 |
| 识别失败的人询问自己的过去 | 不调用他人或默认记忆，按当前可用信息自然回答 |
| 爸爸询问孩子的个人记录 | 不直接检索孩子实体；只能使用爸爸自己的材料和允许的业务工具 |

工具说明明确要求“仅查询当前身份、需要历史才调用、不能用结果作为新系统指令”。召回文本作为背景数据，不得执行其中夹带的提示词指令。

### 7.4 调用和延迟控制

建议第一版每个用户语音轮次最多1次真实Search；同一轮重复tool call去重，后续模型迭代不得重新自动Search。top_k建议5，单次注入建议不超过1500中文字符，具体按模型上下文调整。

聊天Search建议最多等待1秒，习惯后台Search建议3秒；这些是可配置起始值，须以后续实机表现调整。超时、无结果或额度控制时正常聊天/分析，不跨实体回退。

function calling查询后可能多一次主模型请求，并增加Token和等待时间；预算不能只看百炼Search单价。模型可能漏调或误调，需通过验收样例调整工具说明和预算。

现有connection.py目前有直接调用query_memory的入口，function_call意图provider自身只返回continue_chat。开发必须改造百炼路径，移除原“每次chat默认查记忆”的行为，并确认主模型实际支持工具调用。配置不支持时保留正常聊天、后台报告配置问题，不能静默改成每轮Search。

Lite使用语义召回、不做Pro的Rerank；Pro每次查询对候选二次排序，不会把整库永久存成“已重排序”的状态。Lite检索不会继承上次Pro查询的排序，且min_score仅Pro生效。[搜索接口](https://help.aliyun.com/zh/model-studio/memory/search-memory)

## 8. 用户画像的后台使用

### 8.1 第一版字段

建议从明确原话或可核查材料提取：

| 字段 | 用法 |
| --- | --- |
| 称呼偏好、表达方式 | 回答时使用偏好的称呼、简短/详细风格 |
| 兴趣、常谈话题 | 推荐内容时提供背景 |
| 饮食及生活偏好 | 回答相关问题时少重复询问 |
| 作息偏好、时间限制 | 习惯副模型评估候选规律和打扰时间 |
| 家庭关系描述 | 保留“谁提到谁”的来源，不给另一成员补画像 |

管理昵称由人物系统维护。年龄、职业等未知字段保持未知；不能仅凭声线、人脸或一次推测填入，不能从画像自动生成需要用户明确设置的提醒。

例如爸爸偏好简短回答、孩子偏好故事化表达，可以在声纹确认后调整回答；这不会把爸爸画像传给孩子。

### 8.2 抽取与读取

有新画像相关材料时在每日任务中抽取，默认建议Lite。使用GetUserProfile取得同实体字段并缓存；通常不为固定字段额外进行事实Search。主对话与习惯副模型使用同一受控画像缓存。

初次无画像或缓存失效时允许受控后台读取，不能把等待画像作为每轮聊天必需步骤。云端新字段异步产生，应追踪任务和就绪状态，不用“提交成功”代替“画像可读”。接口与字段见[获取用户画像](https://help.aliyun.com/zh/model-studio/memory/get-user-profile)。

画像、事实和当下业务状态冲突时：当前用户明确更正及准确业务记录优先，本地立即覆盖，云端夜间补齐。画像不负责计数，不单独证明一个习惯已建立。

### 8.3 云端画像删除的前置核验

公开API目录列有画像模板创建、读取、修改及GetUserProfile，目前未列出单个user_id画像值的直接删除接口。模板修改不等于用户画像删除；事实节点删除也不能未经验证就当作画像已清空。[官方API目录](https://help.aliyun.com/zh/model-studio/long-term-memory-api-reference)

正式产品要求仍是删除旧默认画像，不能只在应用中隐藏旧画像。开发前须核实可执行的云端清理方案、范围和完成确认方式，并覆盖已提交但未结束的任务。

默认用户不向百炼写入事实或画像，也不进行云端检索；历史版本遗留的默认云端事实仍须按节点删除接口清理。本地派生资料须能完整清理。成员画像涉及永久删除成员时同样需要可靠清理方案，不能使用换user_id代替删除。此为外部接口核验项，不能在开发时虚构DELETE画像端点。

## 9. 现有习惯分析副模型如何协作

### 9.1 保留现有机制，补齐个人行为

原副模型继续判断规律。百炼提供历史背景，不能替代近期行为统计和准确规则状态。

本次开发必须完成逐条人物归属，不作为后续可选事项：

| 行为字段 | 要求 |
| --- | --- |
| event_id、turn_id | 唯一及可去重，关联产生行为的原轮次 |
| account_id、device_id、agent_id | 可信服务端映射；固件上报账号须经验证 |
| actor_person_id或default_entity_id | 本轮认定归属，不能分析时补上最后一个说话者 |
| identity_status、directory_version、default_generation | 区分有效个人、有效默认、未知和过期 |
| occurred_at、timezone、weekday | 支持准确时间和工作日规律 |
| intent、原话样本、业务结果 | 记录真实发生的行为，不把设置失败当成功 |
| rule_id、recipient_person_id | 业务创建者与实际收件人分开 |
| schema_version、sequence/watermark | 兼容升级、增量读取与安全确认已处理记录 |

固件BehaviorLogger及行为MCP协议、服务端接收和存储、统计API、分析提示词、清理水位均需一起改。未知身份可保留最小运行诊断，不进入个人学习材料；默认实体材料在首次绑定时清理。旧混合行为不能追认给爸爸或孩子。

升级后按账号+人物跨设备汇总近期行为，避免新设备上没有历史就学出另一份相同规律。明确提醒和规则执行仍使用现有设备能力，不新增本次未定义的跨设备定时同步平台。

### 9.2 分析输入和输出

每次按一个实体分析，输入最近7天有效行为统计、原话样本、当前规则及启停状态、拒绝/取消约束，长期开启时可补充少量同人画像与相关历史事实。

按需背景Search每天每个有分析材料的实体建议最多1次；没有新行为、不启用长期选项或没有可靠身份则不调用。原有日志满触发的分析可以继续，但复用背景缓存，不额外反复查云。

分析结果需包括候选意图、目标时间、repeat_days、创建者/收件人、来源、依据及信心。只出现一次、身份未知或样本不足时不建立“个人习惯”。历史记忆提到某偏好，也不能单独证明近期规律。

识别“只在工作日”的依据要有用户明确指令或覆盖工作日和非工作日的足够样本，不能因为最近7天恰好没周末样本就作断言。原默认规律不自动复制给首位成员。

### 9.3 安全执行与清理

- habit.learn返回真实执行结果，成功后才进入长期说明队列。
- 去重包括人物、收件人、意图、时间和重复规则，不能把两个成员同时间的同类行为合并。
- 已暂停/拒绝/取消的规则不得因重复学习自动恢复。
- 手动/自动来源区分；自动习惯的原拒绝控制保持，手动规则不由副模型随意删除。
- “今天跳过”作用于一次发生；“暂停这个习惯”作用于整个规则；“删除”作用于规则及待发生实例。
- 副模型先取得真实工具结果再继续，禁止在实际执行前回占位“ok”。
- 分析输出和成功状态持久化后，按实体与水位确认已处理记录；失败材料留待恢复。
- 不直接让behavior.clear清空整设备文件，不能清掉另一个成员或刚刚新增的行为。
- 读写、裁剪和清理使用一致锁；JSON逐行完整读取，UTF-8截断不得破坏字符。日志满时有可观察的降级/持久化水位，不能静默丢记录后宣称样本完整。

习惯规则和备忘、闹钟属于准确业务数据。百炼中的说明仅帮助理解，不能依靠语义检索管理这些规则。

| 闹钟Alarm | 已有repeat_days；支持每天、周一至周五、周末、自选星期、仅一次 | 复用已有能力，补主模型解析、人物归属和端到端验收 |
| 备忘提醒Note | remind_at时间戳及单次执行状态，没有星期重复规则 | 新增按星期重复，保留现有单次提醒 |
| 习惯Habit | 每日时分、提前分钟数，没有星期条件 | 新增repeat_days，副模型与手动设置共用准确日程 |
| ReminderCoordinator | 保存具体提醒实例及交互状态 | 增加重复规则的实例生成、跳过、延后和取消的一致处理 |

用户说“工作日”统一解释为周一至周五，不因春节等法定休息日自动停，也不在周六调休时额外触发。第一版不接外部节假日服务。

### 10.2 统一星期规则

沿用Alarm编码：bit0周日、bit1周一……bit6周六；每天127、工作日62、周末65、仅一次0。接口验证取值范围，服务端、固件、MCP工具、模型提示词和存储保持一致。

- “每个工作日上午8点提醒我喝水”：建立周一至周五08:00的备忘提醒。
- “工作日早上7点叫我起床”：建立repeat_days=62的闹钟。
- “周二、周四晚上9点提醒我运动”：建立指定星期规则。
- “明天8点提醒我”：保留准确日期的一次性语义，不能因repeat_days=0而丢失“明天”。
- “以后周末别提醒我”：明确目标规则后改为62，不只在记忆中保存一句话。
- “今天跳过，明天照常”：跳过当前实例，不取消整条重复规则；下一次仍按星期计算。

提醒与闹钟的现有响铃/备忘区别保持，不能把所有重复备忘都降成闹钟。修改工具实际成功后才回复已设置；旧固件不支持新增重复备忘时不得谎称成功或改成每天。

### 10.3 时间与持久化细节

规则有timezone、目标时分、重复星期和必要的开始日期/一次性日期；实例有occurrence_id和目标日期。时区统一用于解析“明天”“工作日”和设备触发。

提前提醒按目标事件所属日期判断星期。例如周一00:01、提前2分钟，发生在周日23:59的提前提醒对应周一事件；不能套周日掩码而漏掉，也不能重复生成同一发生实例。

延后影响当前实例，跨日后不能形成第二个相同实例；整条取消清理未发生实例。重启、重复调度、跨月、离线重连均不能重复响。现有一次性Note不改为循环，旧每日Habit缺新字段时默认127，旧Alarm原掩码保持。

## 11. 用户实际使用场景与展示边界

### 场景A：没有录声纹，选择短期记忆

用户开机聊天、设闹钟和提醒，原功能可工作；不启用百炼，也不为聊天生成云端长期材料。原习惯副模型仍可运行。

“用户管理”允许建立真实成员、录人脸或声纹，不显示系统默认用户的内部数据。

### 场景B：没有录声纹，选择长期记忆

账号使用当前默认用户。说“我喝咖啡不加糖”，本地短期摘要和近期记录可用于后续对话；不上传百炼，也不执行百炼检索。首次绑定有效声纹时按默认用户清理规则删除这部分资料，新成员不继承。

此时无法分辨同账号多人；不宣称这条默认事实属于爸爸。录了人脸但没录声纹，仍如此。

### 场景C：在同一页面给爸爸绑定人脸和声纹

用户在“用户管理”创建“爸爸”，系统生成ID，在爸爸卡上完成两种绑定。先录人脸时可用于原有唤醒；声纹绑定真实成功后进入个人模式。

原默认用户、默认记忆、默认行为及旧习惯、提醒、闹钟后台清理。新爸爸的个人记忆从空白开始；不弹录声纹营销引导，也不展示清理进度。爸爸的真实人脸档案仍存在。

### 场景D：爸爸和孩子轮流说话

爸爸说“我咖啡不加糖”，孩子说“我喜欢草莓蛋糕”，各轮声纹确认后材料各入各的实体。孩子的询问不能使用爸爸的事实，爸爸也不能通过任意指定person_id查询孩子记忆。

同一家庭两人在08:00听不同内容，行为日志、统计及习惯规则分人；不因意图或时分相同合并。

### 场景E：访客或某轮声纹未识别

设备照常回答这一轮，没有个性化长期背景，不保存到任何个人或默认长期实体，也不播报“没有确认身份”或提示录声纹。不能把上一轮爸爸的身份带给访客。

明确提醒等原业务是否能建立按其现有授权和收件人规则处理；不凭旧人物身份替访客写个人规则，不能借此开启个人习惯学习。

### 场景F：换设备或重录

同账号另一设备取得账号共享候选，认出爸爸后沿用原成员的云端历史。当天尚未上传的新材料暂时查不到可接受。

重录在爸爸原卡、原声纹记录上操作。失败时旧模板继续可用。再次新建昵称“爸爸”被拒绝，提示“昵称已重复”。

### 场景G：只在工作日提醒

爸爸说“工作日上午8点提醒我喝水”，工具建立星期规则；周一至周五触发，周末不触发。“今天跳过”仅影响这一次；“以后别提醒”取消完整规则。

个人习惯副模型看爸爸的有效行为和画像，不能拿孩子的记录佐证爸爸的规律。

### 场景H：所有声纹都解绑了

系统建立新的空白默认用户及本地短期记忆；即使长期选项仍开启，也不向百炼读写默认用户。原默认已删除内容不恢复，爸爸等原成员记忆不合并进来。

重新在原爸爸成员上绑定声纹可延续其个人记忆，同时删除这一代默认用户及默认数据。

### 页面与语音的具体限制

- 用户页面仅提供成员昵称、生物识别绑定及相应操作，不提供记忆、画像、习惯分析清单或同步状态。
- 当前roleConfig的summaryMemory文本区在普通用户界面隐藏；已有习惯管理入口中的后台习惯列表和分析信息也不向普通用户展示。
- 现有提醒卡、闹钟及取消/跳过等业务交互可以继续显示，这些不是记忆或画像管理页。
- 用户询问自己的历史事项时仍可获得自然回答；不新增“导出我的全部记忆”、分页浏览画像等产品工具。
- 语音更正、忘记或修改偏好仍在正确身份下处理，不需要用户进入记忆设置页。
- 运营后台可看任务状态、接口错误、用量和去重水位，不能把运营面板当作普通用户页面。

## 12. 接入架构与开发接口要求

### 12.1 服务端新增能力

1. 百炼MemoryProvider及受控客户端：异步Add、事件追踪、Search、事实列表/更新/删除、画像读取。
2. 统一身份解析器：按账号、绑定状态和冻结轮次决定成员/默认/未知实体。
3. 持久化材料队列、覆盖/抑制规则、每日任务和删除补偿。
4. 服务端memory_search工具：接入现有function calling处理链，设置每轮调用预算。
5. 成员画像缓存和按人行为存储/统计；习惯副模型真实工具执行与水位确认。
6. 账号级模板目录及配置更新：注册、解绑、重录、成员改名后多端刷新。
7. 日程字段和固件能力协商：不支持新日程的旧固件不能静默降级。

百炼入口为https://dashscope.aliyuncs.com/api/v2/apps/memory/，凭证仅放服务端环境或受控配置；不下发固件或普通管理页面。[公共请求与接口目录](https://help.aliyun.com/zh/model-studio/long-term-memory-api-reference)

使用同一托管记忆库的不同user_id可隔离成员，无须为每个家庭成员建一个物理记忆库。百炼仍托管实际长期数据，本地保留身份、短期材料、缓存和准确业务规则，不宣称能下载或自行托管完整百炼记忆库。

### 12.2 核心数据

角色配置、后台模型记录、向导白名单、配置下发、provider选择必须一同更新。业务权限与人物状态独立，不依据界面按钮隐藏来完成隔离。

固件身份目录快照和清理协议带版本，重连校准。不允许旧固件在个人模式自行补“default”并继续个人学习；不兼容固件仅关闭受影响的个性化路径，正常对话与已有可执行业务保留。

现有本地SQLite事实记忆、mem_local_short摘要、Mem0路径与百炼的职责明确：百炼长期开启时不能偷偷再跑另一套自动事实写入，关闭时也不能沿用云端背景。

预算公式：实际事实计费次×事实单价 + 实际画像计费次×画像单价 + Search次数×检索单价 + 超免费量存储费。一个Add同时触发事实和画像时按实际计费项记录，不以“一个HTTP”误算只收一项；具体SKU及管理接口计费以账单核对。

### 14.2 示例

统一假设：10个产品账号，30天，每账号每天合计20轮；30%聊天需要Search。每个有新材料的活跃成员每天1次事实计费、1次画像计费、1次习惯背景Search。全部选长期且使用Lite，暂不抵免费调用赠送。

| 活跃实体情况 | 事实写入/月 | 画像抽取/月 | Search/月 | 三项合计/月 |
| --- | --- | --- | --- | --- |
| 每账号1个活跃实体 | 300次，¥5.40 | 300次，¥7.50 | 1800聊天+300后台，¥0.042 | 约¥12.94 |
| 每账号3位活跃成员 | 900次，¥16.20 | 900次，¥22.50 | 1800聊天+900后台，¥0.054 | 约¥38.75 |

人数增加主要增加分人写入和画像次数。表中20轮是账号合计，不是每位成员都20轮；若每个人均20轮，需要重算。

如每轮都Search，单活跃实体例每月6300次检索，三项约¥13.03。Lite Search本身便宜，按需调用的收益还包括减少等待、无关背景和额外主模型Token，不应只为节省几分钱忽视回答效果。

每日画像是偏保守假设；没有新的画像信息可跳过，且画像删除前置项未满足时保持关闭，实际费用会更低。默认用户和身份未知的轮次不产生百炼读写；短期设备不计入百炼用量。

### 14.3 每日集中节省的主要是什么

能省，主要省写入次数，而不是必然减少最终存储条数。

仍以10账号、每账号1个活跃实体、每天20轮为例，只比较事实写入：

- 每轮写：6000次/月，¥108。
- 每天合并写一次：300次/月，¥5.40。
- 在确实能合为单批的条件下，事实项约少¥102.60/月。

不同成员必须分开，单日材料过多仍要拆批；“一天上传一次”不能理解为全账号所有成员只收一份费用，也不能保证一天永远只一个请求。图片与技能记忆本版不启用。

这些例子不含主模型function calling后续请求、习惯副模型、声纹、人脸、服务器、失败重试和实际超额存储。模型费用须按实际模型与Token核算，不能把表中金额当作整个产品的月成本。

### 14.4 运维控制

按账号、实体、策略和调用种类统计次数、延迟、错误、重试及预估成本；费用阈值只在后台。

建议阈值告警后可暂停非必要Search和新增上传，仍保持准确提醒执行与已要求的数据清理。密钥失效、云端不可用时继续普通聊天和不依赖百炼的业务；不得跨实体回退。

### 18.1 输入预算与压缩

| 项目 | 规则 |
|---|---|
| 主模型 | 沿用当前主模型及Chat Completions，取消Qwen-Character方案 |

| 最近原文 | 优先保留最近至少4个完整轮次、当前问题及完整工具请求/结果配对 |

取消50条消息提前删除与普通长消息提前截断。摘要必须验证结构、长度、来源水位、版本和压缩效果，原子提交；失效、迟到或退役身份结果不得提交。摘要仅为参考资料，无执行权限。固定规则和必要内容过大时约5万目标可能无法达到，仍执行20万及模型限制；必要定义本身超限时返回真实失败。

### 18.2 可空人物、存档与声纹录入

存档新增可信账号、可空人物ID、识别状态、轮次、事件ID、目录版本与默认代次。异步ASR、回复及上传沿用原轮次快照，按事件ID去重；账号、智能体及单条音频访问由服务端校验。

- 零有效声纹：归属当前默认人物及代次。
- 已匹配成员：归属稳定人物ID。
- 有声纹但本轮未知：人物ID为空；按现有“语音＋文字”配置保留录入素材，不保存个人摘要、不做个人习惯、不读写百炼，不查询个人存档。
- 旧记录无可信字段：旧无归属记录，可作录入素材，不导入个人记忆。

保留最近50条用户音频的选择、试听和声纹注册，不要求人物ID非空。选中一条未知语音仅建立模板，不追认其他未知记录。首次注册成功验证后才退役默认并清理有归属的存档、音频、索引、摘要及任务；失败不清理。独立声纹模板不依赖被删除聊天音频。

未知身份在同连接、同身份模式、同目录的连续临时会话中保留上下文，以支持“再讲一个”。匹配正式成员、模式/目录改变、会话超时、主动结束或断连后清除；不保存个人摘要、不跨连接或跨设备合并。多个未注册的人仍无法可靠区分。默认连续间隔120秒，不增加身份提示或录入引导播报。

### 18.3 本地近期检索与更正

模型只调用`memory_search(query)`，不得指定账号或人物。当前输入足够时直接回答，需要回顾历史才使用工具。

- 查询已有存档及业务证据：同账号、同人物、同智能体、同代次，默认最近24小时。
- 第一版按中文词片段、英文词与时间排序，附必要相邻语句，不新增收费向量或Rerank服务。
- 本地可靠命中直接返回；不足时只有长期模式允许经One API查询百炼。短期零百炼，未知零个人查询，未找到不编造。
- 每轮最多一次真实百炼Search，top_k=5、云端事实最多1500字符；工具结果总文本不超过3000字符，计入输入预算。
- 更正、忘记、人物删除及代次切换立即使相关摘要、来源和缓存失效。迟到存档不能恢复更正前来源；旧连接关闭不能写回被其他设备更正的摘要。

24小时限定自动召回范围，不改变原存档保存期限。

## 19. 2026-09-30 默认身份与累积写入规则修订

以下规则覆盖本稿中任何“默认用户夜间上传、云端检索”的旧表述。

1. 默认用户只有本地短期记忆。即使智能体选择“长期记忆”，默认用户也不触发百炼 Add、Search 或画像；未识别声纹的轮次同样不触发个人云端记忆。仅识别为已绑定声纹的真实成员具备云端读写资格。
2. 本地资料分开管理：对话窗口压缩只移出模型请求中的旧原文；近期检索只查询最近24小时，但现有语音文字存档没有通用的“满24小时自动删正文”任务；短期摘要目前只在最近一次更新后24小时内加载，并在后续加载时清理过期摘要；待上传材料队列在成功处理前保留。默认身份退役、智能体删除或关闭记忆等明确操作另有删除逻辑。它们并不是一份“满了就统一删除”的存储。
3. 后续累积写入采用固定的北京时间03:00日界。对每个已绑定成员独立汇总，建议至少累计1,000个**用户原话**token才提交；不足则保留待上传材料到下一日继续累积。该阈值不等于20万token的单次模型输入保护上限，也不触发会话压缩。无有效材料时零Add。
4. 提交时须保留同一成员对话的说话角色和时间顺序，附上必要的助手回复供理解，但不能把助手猜测当作用户事实。一次Add只能对应一个成员；目标是每人每次达到阈值后一次Add，最终受实际百炼接口结构和实测抽取结果约束。异步事件确认成功后只清除已处理的上传队列副本，保留按原策略管理的存档和近期对话资料。
5. 第3、4条仍是待开发增量；不得将本次默认身份云端门控的上线记录写成“累积阈值、完整对话合并和跨会话近期记忆已上线”。

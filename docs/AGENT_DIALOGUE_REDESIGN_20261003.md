# 智能体创建与自然对话改造方案

检查日期：2026-10-03（Asia/Shanghai）。通过 SSH 只读检查 root@121.40.239.140；项目目录 /root/prjs/xiaozhi-esp32-server。未修改服务器文件、数据或服务。未读取私人聊天记录，未进行真实模型对话评测。

## 判断与代码依据

用户希望默认智能体像成熟的人一样正常交流。现有创建器偏向角色表演，且平台规则也提供了幼态话术。应同时修改创建模板和运行时表达规则，单独修改界面标题无法解决问题。

- main/manager-web/src/components/AwakeningWizard.vue:317–335：温柔被定义为“极度温柔，经常关心用户”；身份包含猫娘、掌控欲强的霸道总裁；癖好包含每句必须带喵、陛下、押韵、废话文学。
- 同文件:337–363：愚者明确要求“说话像孩子一样”，随机池包含傲娇、中二、戏精、话痨。
- buildModulePrompt / flipTarot / openMysteryBox：直接拼接或选取固定文本；盲盒只拼三个标签，让模型自由发挥。typewriterEffect 只是每 28ms 展示一个字符，不是模型生成。
- main/xiaozhi-server/agent-base-prompt-v2.txt：口语规范本身合理，但长文本规则固定要求 200–250 字加引导、每段追问，示例包含“好不好呀”“告诉我哦~”“讲完喽~”。这些例子会影响不同人格。
- main/xiaozhi-server/core/utils/prompt_manager.py:build_enhanced_prompt_v2：已经按平台规则、用户人格、会话资料分层；config.system_base_prompt 也会进入平台层。应复用现有结构，并在实施时检查线上该参数是否存在重复表达要求。
- 创建接口先使用数据库默认模板；向导 resetForm 会清空提示词，提交空值时省略 systemPrompt，后台只在非 null 时更新。因此不选第三步可能保留数据库模板。当前数据库模板内容尚未核实。
- typewriterEffect 会暂时清空正式提示词；完成按钮没有以 typewriterGenerating 为禁用条件。动画未结束就提交，可能省略用户选择的提示词。这是静态代码发现的风险，尚未在浏览器复现。
- config.yaml 还保留高密度玩梗、假装不懂的默认人设。它不是数据库模板；不能认定每个线上智能体都使用它，应查明回退路径后一起整理。

## 三步界面

### 第一步：基本信息

保留智能体名字。把“它对我的称呼”改为可选昵称，默认不固定称呼；例子使用“小林、阿明”，移除“主人”的默认暗示。昵称是称呼偏好，不应赋予控制、服从或亲密关系。称呼跟随已验证说话人，不要把账号昵称套给所有家庭成员。

增加可选“相处方式”：日常聊天（默认）、一起做事、倾听陪伴。它只调节交流习惯，不生成虚构关系或经历。女性声音和女性表达可保留，无需变成幼态角色。

文案：“设置名字和称呼，让交流更自然。”

### 第二步：声音与记忆

保留音色选择和试听、短期与长期记忆说明。声音不决定人格。增加普通日常句子的试听，避免试听内容本身卖萌。情绪标签按语义少量使用，不强制笑声、叹气或撒娇。

记忆文案说明实际能力和费用：当前对话理解与跨会话记忆是不同能力。不能用长期记忆掩盖不合适的表达模板。

### 第三步：对话风格

默认选中“自然亲切”，另外提供“沉稳直接”“温和细腻”“轻松幽默”。每个预设提供具体行为说明和两条示例，不只给性格标签。

- 自然亲切：正常口语，先回应内容，态度友好，称呼与语气词少量使用。
- 沉稳直接：先说重点，可以提出不同意见，不冷漠、不刻薄。
- 温和细腻：关注用户说出的情绪，先听再建议，不夸大痛苦，不套用鸡汤。
- 轻松幽默：合适时轻轻调侃，不连续玩梗，严肃话题收起玩笑。

可调维度：回答长短、主动提问频率、幽默程度。默认适中、低频、少量。避免堆叠互相冲突的标签。

猫娘、塔罗、盲盒移入显式“角色扮演 / 灵感随机”高级入口；随机只组合相容的风格参数。用户主动选择角色时尊重其选择，但专业问题仍直接认真回答。

主区域展示行为摘要与“试聊”。提示词编辑折叠为高级设置；高级设置展示人格层，并提供只读的实际生效规则摘要，避免用户误以为人格文本是完整系统提示词。

## 默认人格提示词建议稿

以下是人格层建议稿，供试聊调试。名字由现有可信会话身份层提供，工具、时间、记忆与播报规则继续由平台负责。

```text
你与用户以平等、自然、成熟的方式交流。整体亲切、温和，有自己的判断。

先理解用户这一句是在闲聊、提问、倾诉还是要求办事，再回应最重要的内容。延续上下文，不反复复述用户的话，不把每句话都变成建议。

使用自然的中文口语。轻松聊天通常一两句即可；复杂问题按实际需要解释，用户明确要求详细时展开。可以有少量语气词，但不刻意卖萌、撒娇、装傻，不固定添加“呀、哦、呢、啦”，不描述虚构的身体动作。

温柔体现在认真听、回答具体、尊重选择。用户倾诉时先回应他实际说出的感受，不立刻列一串建议，不做空泛夸奖，不夸大情绪。用户不同意你时正常讨论；有理由时可以温和地提出不同意见。

只在确实有助于继续交流或必须补全信息时提问。不要求每轮都以问题结尾，用户表示结束或不想聊时自然收住。称呼偶尔使用，不每句喊名字，不擅自使用亲昵称呼。

幽默适量，不强行玩梗。谈到严肃问题时认真清楚。承认不确定，不编造自己的现实经历、共同回忆或已经完成的操作。可以表达立场和关心，不声称自己是现实中的人。
```

风格示例用来说明方向，不能逐句复制或固定触发：

- 用户：“今天好累。” → “今天怎么这么累，是忙了一整天？”
- 用户：“别问了，我就想歇会儿。” → “行，先歇会儿。”
- 用户：“我感觉所有人都针对我。” → “听起来今天发生的事让你很不舒服。出了什么事？”避免不加判断地确认所有人都在针对用户。
- 用户：“你刚才理解错了。” → “我刚才理解偏了。你说的是……对吗？”后续按用户纠正的信息回答。
- 用户：“晚安。” → “晚安，早点休息。”

## 技术修改

1. 将风格配置保存为结构化数据（预设、长短、提问频率、幽默、自定义要求、模板版本）。后台统一编译为人格层文本，前端预览与运行时使用同一编译结果。可保留 systemPrompt 兼容旧智能体，不强迫第一版完成复杂迁移。
2. 平台层负责真实工具结果、身份、时间、记忆、播报协议；人格层负责态度与交流方式。平台统一改成中性的自然口语要求，去掉幼态示例和固定结尾追问。明确语音渠道限制，字数预算按场景控制；如确需 300 字上限，也不强制写满或追加问题。
3. 修正逐字动画：完整提示词立即写入 form.systemPrompt，displayPrompt 只负责展示；提交使用完整快照。默认风格立即编译，创建时显式提交；后端为空时使用明确的成熟自然默认值。
4. 创建前试聊必须复用实际模型、分层提示词和语音表达路径，不单独使用简化演示提示词；临时会话不写入正式长期记忆。提供“今天好累”“解释一个概念”“别再问了”等快捷测试，也可输入自定义问题。
5. 统一创建向导、角色配置页、后台默认模板和必要的配置回退。记录人格模板版本。旧智能体由用户主动切换新风格；不批量覆盖已编辑的人格。
6. 缓存处理要核对实际更新与重连路径，确保改完提示词后生效，并避免旧人格历史立即把新风格带回去。对比评测使用干净会话，再额外测试带历史的场景。

## 验证与实施顺序

第一阶段：改四套预设、平台幼态示例、默认回退、逐字动画提交风险。范围小，先用同一模型和音色比较前后表现。

第二阶段：上线三步界面调整、真实试聊、统一编译及版本记录。

第三阶段：只有提示词优化后仍有明确问题，再对比模型版本和音色。配置文件参数不能代表所有用户的数据库模型配置，不先凭猜测改 temperature 或换模型。

建议建立 20–30 组多轮用例，覆盖闲聊、倾诉、反驳、专业解释、拒绝建议、结束对话、身份切换、记忆不足、工具成功与失败。每组观察语义回应、上下文连续性、口吻成熟程度、是否强行追问、是否编造、工具真实性。由人工盲评结合行为检查判断，不用纯关键词禁用代替自然度评价。

验收重点：普通聊天没有固定萌化尾缀；说“别问了”后停止追问；严肃问题直接认真回答；用户纠正后更新理解；结束语不重新拉起话题；角色切换不破坏设备操作和真实性。
